PsyView log-axis rendering fix
==============================

REPLACE ONLY:
    src/psyview/plotting/axes.py
    src/psyview/plotting/terminal.py

Do NOT replace app.py or the YAML files again.

WHAT WAS ACTUALLY WRONG
-----------------------
The screenshots made the bug unambiguous.

PsyView's terminal renderer did this on a log axis:

    limits in real data units
        -> log10(limits)
        -> Plotext.xlim / Plotext.ylim

But Plotext's log ruler already performs the logarithmic transform internally.
The limits were therefore being supplied in the wrong coordinate system.

That explains every screenshot:

1. PSF
   legend says X = 5 .. 1000
   renderer actually gave Plotext about 0.70 .. 3

   real luminances are 10 .. 403, so essentially all data were outside the
   numerical window and disappeared.

2. CSF
   legend says X = 0.05 .. 100
   renderer actually gave Plotext about -1.30 .. 2

   only spatial frequencies <= about 2 remained visible, exactly as shown.

3. Threshold box
   legend says Y = 0.002 .. 0.02
   renderer actually gave Plotext about -2.70 .. -1.70

   thresholds around 0.004 were outside that raw numerical interval, so the
   box vanished.

4. Staircase
   legend says Y = 0.001 .. 1
   renderer actually gave Plotext -3 .. 0

   contrasts around 0.03 then landed close to the top of the wrong numerical
   range, matching the screenshot.

THE FIX
-------
TerminalPlotRenderer now passes physical limits directly:

    Plotext.xlim(5, 1000)
    Plotext.ylim(10, 1000)

and lets Plotext perform the log mapping itself.

SECOND BUG FIXED
----------------
The CSF screenshot also showed:

    Y scale: linear (dataset config)

despite the YAML declaring log.

That happened because axis_policy changed an entire requested log axis to
linear if ANY series contained a zero/negative value. An auxiliary/helper
curve can have a non-positive tail even though all empirical CSF points are
positive.

New rule:

    requested log + any positive plottable values
        -> remain log
        -> non-positive coordinates are omitted from the terminal log plot

    requested log + no positive values whatsoever
        -> fall back to linear

This keeps CSF scientifically logarithmic without allowing an invalid helper
point to destroy the scale.

WHAT STAYS UNCHANGED
--------------------
- fixed x/y ranges across sibling conditions in each hierarchy row
- PNAS CSF YAML: log x, log y, preferred 10..1000, decade expansion
- box plots: local categorical x, shared y
- min/middle/max y labels
- right-hand AXES description
- X/Y user scale controls
- threshold/fit/error calculations
- empirical data
- GitHub repositories

VALIDATION
----------
The patch includes regression tests for:
- PSF shared log x range 5..1000 staying in physical coordinates
- a CSF remaining log when an auxiliary curve contains a negative tail
- fallback to linear only when a requested log axis has no positive values

RUN
---
    .\run_psyview.bat
