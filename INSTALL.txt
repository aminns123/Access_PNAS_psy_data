IMPORTANT FIX
-------------
The failed versions replaced the proven row-axis calculation with a new
sibling/raw-scale pipeline. That was too invasive.

This version DOES NOT replace it.

The sequence is now:

    existing plot
      -> existing known-good shared row limits
      -> optional YAML scale/rounding/preferred bounds
      -> renderer

The YAML layer never recalculates all sibling extents itself.

If a YAML/user scale would actually CHANGE a PlotSpec from linear to log (or
vice versa), PsyView clears that axis's old manual limit and lets the renderer
recalculate safely. This prevents a limit calculated in one scale from being
used as though it belonged to another.

PNAS CSF DEFAULT
----------------
Still declarative:

    scale: log
    limits: row
    rounding: decades
    preferred_min: 10
    preferred_max: 1000

So, when compatible with the data:

    18..850  -> 10..1000
    8..850   -> 1..1000
    18..1800 -> 10..10000

X / Y
-----
X toggles a numeric X axis between the current scale and the alternative.
Y does the same for Y.

Pressing the same key again returns to dataset/default.

Categorical box-plot X axes are not toggled.

No empirical data, thresholds, fits, or repositories are changed.
